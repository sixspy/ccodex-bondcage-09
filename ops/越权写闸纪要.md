# 越权写闸纪要（2026-11-22 锁定）

> 当日锁死，不得当日翻案。偏离本纪要的改动按「越权偏航」记并拒写。

## 事故

无写权柜员（clerk）打开解笼页仍能提交拨付：鉴权层只挡 `viewer`，`clerk`
被当作可写角色放进解笼/罚没写口。结果正式拨付册多一行、账户余额与冻结被
扣、审计留下 `cage_release` 的无写权出金痕迹。鉴权门闸形同虚设。

## 口径（单一口径，两边不得混用）

- **只取乙路径：审批影子 + 服务端代写。**
- 无出金写权角色（`viewer`、`clerk`）对出金类写口**零写入**：
  - 不进鉴权门闸后的任何业务写；
  - 业务表（`releases`/`forfeits`/`cages`/`bond_accounts`）零增零改；
  - 失败响应不落半成品；
  - 仅允许建**审批申请影子单**（`approval_requests`）。
- 正式拨付/罚没只由**管理员**在审批通过后由服务端代写；驳回时影子作废、
  正式表零改。
- 立即执行口径（甲路径）**未采用**，避免与乙路径双口径混用。纪要仅登记
  甲路径为「被否候选」，不计为实现。

## 角色矩阵

| 角色 | 出金类写口（解笼/罚没/增补/拆笼） | 非出金写口（开户/入金/核验） |
|------|-----------------------------------|------------------------------|
| admin | 直接写（持笼锁） | 直接写 |
| clerk | 403 拒写；可建影子申请 | 允许 |
| viewer | 403 拒写；可建影子申请 | 403 拒写 |

- 「出金类」= 资金离开冻结/进入罚没或正式拨付册的写口：`/api/releases`、
  `/api/forfeits`、`/api/topup-stub`、`/api/split-stub`。
- 「非出金写口」= 开户、入金、核验（不动用可用额出系统）：clerk 可写。
- viewer 对一切写口 403。

## 两人同笼争用

- 两个写角色抢同一笼的锁，仍按 `cage_locks` 抢锁：后到者 409，**只留争用痕**
  （`contention_log`），业务表零增。
- 争用痕必须在事务回滚后仍可见（先持久化争用，再抛 409）。

## 五页同源

解笼页、罚没页、审计页、账户页、对账页的数字必须同源：

- 解笼页/罚没页：只显示正式表（`releases`/`forfeits`），影子单单独标注，不混入正式册。
- 审计页：显示 `越权偏航`、`审批申请`、`审批通过/驳回`、`争用` 痕迹。
- 账户页：余额/冻结来自 `bond_accounts`，由正式写口扣减。
- 对账页：`available + released + forfeited == amount`（同笼代），影子单不入账。

- 甲/乙两口径混用 → 记越权偏航，拒写。
